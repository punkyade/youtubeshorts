# 숏폼 대본

숏폼 대본은 글이 아니라 **편집 지시서**다. 각 비트에 "화면에 무엇이 보이고, 무엇이 들리고, 무엇이 쓰여 있는지"가 초 단위로 있어야 촬영·편집자가 바로 쓸 수 있다.

입력: `02_concepts.json`의 `selected_id` 기획안, `content/creator_profile.md`, 근거 트렌드(`trend_refs`가 가리키는 항목의 hooks)
출력: `_workspace_shorts/03_script.json`, `_workspace_shorts/03_narration.txt`, `_workspace_shorts/03_script.md`(사람이 읽는 표 형식)

## 구조

| 구간 | 길이 | 할 일 |
|---|---|---|
| 훅 | 0~3초 | 스크롤을 멈추게 한다. 결과·반전·질문·금지("이거 하지 마세요") 중 하나. 인사·자기소개 금지 |
| 전개 | 비트당 3~7초 | 한 비트에 정보 하나. 매 비트 화면이 바뀐다(컷, 줌, 자막 변화) |
| 보상 | 마지막 3~5초 전 | 훅에서 약속한 것을 준다. 약속을 안 지키면 완주율보다 신뢰가 먼저 무너진다 |
| CTA | 1~2초 | 하나만. "저장해두세요" 또는 "2편 보기" 등. 루프형이면 첫 장면으로 자연스럽게 이어지게 |

훅은 트렌드 보고서의 `hooks` 패턴에서 출발하되 그대로 베끼지 않고 기획 소재에 맞게 바꾼다. 훅 후보를 3개 쓰고 가장 구체적인 것을 고른다 — 숫자, 고유명사, 눈에 보이는 결과가 있는 쪽.

## 분량 계산

- 한국어 내레이션은 초당 약 **4~5음절**(빠른 쇼츠 톤 기준 5). `length_sec × 4.5`음절을 넘지 않게 한다. 넘치면 문장을 자르지 말고 정보를 뺀다.
- **프로필에 음성(TTS) 설정과 초당 음절 수가 있으면 그 값이 우선이다** — 실제로 그 목소리로 읽은 속도라 일반 기준보다 정확하다. (예: SunHi +12% → `length_sec × 4.3`)
- 화면 자막(caption)은 한 번에 **14자 이내 2줄**까지. 내레이션을 그대로 옮기지 말고 핵심어만.
- `t_start`/`t_end`는 0부터 `length_sec`까지 빈틈·겹침 없이 잇는다.

## 내레이션 (TTS 연결)

`narration_text`와 `03_narration.txt`는 이 프로젝트의 TTS(`tts file narration.txt`)로 바로 읽힌다. 그래서:
- 읽는 말로 쓴다: `3kg` → `3킬로그램`, `vs` → `대`, URL·이모지·해시태그 넣지 않음
- 문장 끝마다 마침표를 찍는다 — TTS 청크 분리와 억양이 문장 부호에 의존한다
- 비트 사이 숨 고를 곳은 줄바꿈으로 구분한다
- 얼굴 출연 영상이어도 내레이션 파일은 만든다(가이드 녹음용)

## 제목·설명·해시태그

- 제목: 40자 이내, 앞 15자에 핵심. 썸네일 문구와 같은 말을 반복하지 말고 보완한다.
- YouTube 설명 첫 줄에 핵심 + `#shorts`는 선택. 해시태그 3~5개(넓은 것 1, 분야 2, 구체 1~2).
- Instagram 캡션: 첫 줄 훅 반복, 저장 유도 한 줄, 해시태그 5~10개.

## 03_script.md 형식

```
# {제목}  ({length_sec}초 · {포맷})
**훅:** {line}
| 시간 | 화면 | 내레이션 | 자막 | 효과음 |
|---|---|---|---|---|
| 0–3s | ... | ... | ... | ... |
**CTA:** ...
**YouTube 설명 / 해시태그** ...
**Instagram 캡션 / 해시태그** ...
```

## 자체 점검 (완료 전)

- [ ] 첫 비트에 인사·채널 소개가 없다
- [ ] 음절 수 ≤ length_sec × 4.5 (word_count 필드에 음절 수 기록)
- [ ] 모든 비트에 visual이 있고 연속된 두 비트의 visual이 같지 않다
- [ ] 훅의 약속이 보상 구간에서 지켜진다
- [ ] 과장·허위 표현(“무조건”, “100%”, 근거 없는 효능) 없음
- [ ] narration_text에 숫자 단위 기호·이모지·URL 없음

## 이전 결과가 있을 때

"대본만 다시"·리뷰 이슈가 있으면 기존 `03_script.json`을 읽고 지적된 부분만 고친다. 전체를 새로 쓰는 것은 사용자가 원할 때만.
